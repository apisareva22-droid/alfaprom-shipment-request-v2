# Подключение Google Apps Script

Этот сценарий получает заявку с сайта, создаёт папку для неё на Google Drive, сохраняет до двух прикреплённых файлов, дописывает строку на лист `Заявки` и отправляет уведомление в Telegram.

## Однократная настройка

1. Откройте вашу таблицу «Реестр заявок АЛЬФАПРОМ».
2. Выберите **Расширения → Apps Script**.
3. Замените содержимое `Code.gs` кодом из файла `apps-script/Code.gs`.
4. В настройках проекта добавьте свойства сценария:
   - `TELEGRAM_BOT_TOKEN`
   - `TELEGRAM_CHAT_ID`
5. Нажмите **Развернуть → Новое развертывание → Веб-приложение**.
6. Укажите: «Выполнять от имени: я», «Доступ: все». Подтвердите разрешения Google.
7. Скопируйте URL, который заканчивается на `/exec`, и передайте его сюда.

Токен и ID чата остаются только в свойствах Apps Script. В код сайта и Google Sheet они не добавляются.

## Протокол подтверждения 2

Используйте существующее развертывание и тот же URL: «Управление развертываниями» → «Редактировать» → «Новая версия».

- `GET ?action=health&callback=...` возвращает `protocol: 2`.
- `POST action=submit` проверяет все сведения и сигнатуры файлов, сохраняет сформированный PDF, подписанные вложения и JSON с данными.
- `GET ?action=requestStatus&submissionId=...&statusToken=...&callback=...` возвращает только факт приёма, номер заявки и состояние уведомления. Реквизиты и ссылки на файлы не возвращаются.
- Колонки A:M сохраняют назначение. N:R добавляются для идентификатора отправки, хеша ключа подтверждения, состояния уведомления, ссылки на папку и даты обновления.
- `LockService` исключает одновременную запись дублей. При повторе после ошибки записи переиспользуются папка и файлы.
- Если Telegram не отвечает, заявка остаётся принятой. В колонке P будет `failed` или `pending`; папка и строка реестра сохраняются. Автоматическая отправка в оператор ЭДО/СБИС не выполняется.

Свойства перевозчиков прежние: `PEK_LOGIN`, `PEK_IP`, `DL_API`, `JDE_API`, `JDE_IDENT`, `SDEK_IDENT`, `SDEK_PAROL`. Ключи не переносите в файлы сайта.
